# Kernel-owned front tuning profile qualification

The fresh profile01 candidate follows the physically verified front NV12 queue,
metadata and typed scalar overlays. Every trial flag defaults false. This is a
one-use qualification candidate; no final product or optical quality claim.

Linux request_firmware_direct loads the fixed board/mode data-only file
qcom/sp11/imx681-2560x1440-nv12-v1.bin. Its36744 bytes hold2661 scalar words and
26036 table bytes; no opcode, register address, device address or executable is
interpreted from firmware. The GPL driver schema owns334 instruction shapes,
all addresses, section topology and DMI bindings. A pinned SHA256 admits only
this exact reviewed mode/profile. Internal reconstruction is byte-identical to
the private qualified startup fixture and passes269 corruption cases under
ASan/UBSan without modifying output on rejection. This data provenance does not
establish redistributable independent tuning or Windows optical parity.

No raw command control is registered in this candidate. The first valid typed
request loads, validates and internally queues the startup defaults; later
requests use the proven scalar schema. Public metadata and typed scalars remain
experimental. The internal carrier still uses the retained provider format;
that format is never accepted from userspace in profile mode.

The on-target probe reads only semantic Demux baseline values from the data-only
profile for its2x-gain diagnostic. It uploads no command packet. It verifies the
raw control is absent, four malformed typed packets fail, missing firmware fails
with ENOENT and corrupted firmware fails with EKEYREJECTED before any STREAMON.
Restoring the original profile must allow request5 and the full84-request/80-pair
capture, gain/reset response and safe stop. A root service recovery restores the
verified file if the probe is killed during a negative case. Private data stays
on SP11. Retire the candidate boot/unit/firmware copy after this one attempt.

Remaining product work: actual libcamera pipeline/IPA requests and3A, dynamic
semantic tuning tables, final ABI/clock policy, rear processed capture, reopen,
soak/switch and controlled optical comparison. No bespoke runtime or software
pixel ISP is added.
