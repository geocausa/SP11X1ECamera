# Dormant CDM2.1 power ownership — 2026-10-12

Patch0009 adds independently written parent power ownership to the public
74-patch CAMSS/ISP RFC candidate. Candidate14 has no probe/runtime caller,
DT change, sensor capture, installation or module load.

The parent supplies a reviewed live runtime-PM device and nonempty clock
bundle. No addresses, IRQs, clock rates, regulator/domain/interconnect routing
are inferred. Construction claims one inactive, unused, IRQ-disabled backend
with zero reset epoch. Provider objects, clock array and zeroed helper storage
must outlive the backend. The parent serializes construction, operations and
detach; provider callbacks must not reenter while the power mutex is held.

Acquisition resumes the device and holds one PM reference, then uses kernel
bulk prepare/enable. Partial clock failure unwinds its own references and drops
its PM acquisition, preserving the clock error. Failed PM put latches a fault.
Hold is idempotent. Unused release disables/unprepares clocks before PM put
and is allowed only before any reset attempt or backend quarantine.

Reset marks touched before calling the owned backend. Owner identity and
held/touched/fault state are checked before MMIO. Once attached, raw reset
rejects owner mismatch before MMIO. Every reset attempt, including wrong
version, timeout and success, retains power. There is deliberately no
post-reset release/detach API. Physical bus/DMA retirement and full parent
recovery must be implemented before runtime admission. Ownership is not a
fresh-power certificate.

## Public sources and validation

Four exact Qualcomm GPL files in cdm-power-reference-20261012.json were
reverified by size, Git blob SHA1 and SHA256. Their generic resource sequencing
and DT lookup do not establish an exact X1E CDM route. Current upstream X1E
CAMSS binding lacks CDM register, IRQ and clock data.

Candidate14 ARM64 CAMSS composite and generic ISP objects pass W=1/-Werror
without build warnings/errors. No full kernel/modpost/module or compatible
Golden runtime qualification is claimed. Nine patches replay without fuzz or
offsets across 17 files; 46 other parent CAMSS files are byte-identical.

tools/test-upstream-cdm21-power.py executes complete pinned power/reset/binding
code and six exact functions extracted from pinned kernel clk-bulk.c/clk.h.
GCC and Clang each pass ASAN/UBSAN: 201 power, 659 reset and 899 binding cases,
423965 assertions. Eighteen changed/missing/symlink candidate fixtures are
rejected with unchanged positive controls. Tests cover invalid providers and
ownership, idempotent hold, partial prepare/enable failures at every position
in bundles of 1–4 clocks, PM get/put failures, other-owner reference retention,
all 24 reset ACK orders, and reset failure/success power retention.
PM, clock leaves, locks, IRQ, framework cleanup and MMIO are hosted models;
real concurrency, provider routing, power recovery and retirement are unproven.

Standard patch checkpatch: 0 errors, one FILE_PATH_CHANGES advisory. Existing
recursive CAMSS MAINTAINERS coverage includes the new files. Ignoring that
advisory, and separately checking all four backend files, produces clean
style results. --no-signoff is used; this is not a curated signed submission.
