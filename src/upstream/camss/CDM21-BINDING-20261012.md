# Dormant managed CDM2.1 binding

Patch0008 follows the seven earlier source patches. Candidate12 adds a managed
platform-resource binder and the IRQ-disabled admission path to the actual
CAMSS-compiled CDM2.1 backend. No CAMSS parent probe/runtime call is added.
No DT binding, address, IRQ number, clock or power-domain value is invented or
installed. The pinned upstream X1E CAMSS binding contains no CDM resources.

## Resource and IRQ ownership

The parent supplies reviewed register and IRQ resource names through an internal
typed structure. This is not a userspace register/submission API. Binding must be
serialized with all parent devres acquisition and detach operations.

The binder rejects missing/empty arguments, a missing memory resource, reversed
or unaligned extents, insufficient register span, resource-size wrap or truncation.
IRQ lookup errors, including probe deferral, propagate before acquiring managed
resources. The output pointer is written only after complete success.

A devres group contains the reserved register mapping, zeroed backend state and
exclusive IRQ request. IRQF_NO_AUTOEN keeps the Linux IRQ disabled when requested;
no shared flag or hard-coded trigger type is imposed. Partial failures release
only this group; unrelated parent resources remain. Successful acquisition keeps
managed resources for parent detach. IRQ is acquired last, so managed reverse
cleanup releases it before state and mapping. Framework cleanup here does not
supply hardware quiescence or authorize teardown of active command/image DMA.

The binder performs no MMIO or power operation. Its handler is initialized before
registration and returns without MMIO while inactive. A future parent must
quiesce calls before detach and keep mapping, storage, power and clocks live
through reset. Raw initialization remains available for a separately registered,
enabled exclusive IRQ; managed binding owns an initially disabled IRQ instead.

## Reset admission and pre-command IRQ handling

Managed reset enables the Linux IRQ only after exact version admission, four-bank
mask/readback/drain/clear, pause write/readback, completion reset and fresh software
epoch admission. A failure before that point leaves the IRQ disabled and does not
add another disable depth. A failure after enabling disables it once. Quarantined
instances reject retry without MMIO or additional IRQ depth changes.

An active pre-command handler clears observed status and latches a fault, returning
HANDLED so a level IRQ can deassert. It never adds reset ACK bits or completes the
fresh transaction. The caller checks this fault under the same IRQ lock before
issuing reset, even if the handler has already cleared every status register.
A repeat empty handler observes no pending status. This supersedes candidate10's
pre-command ignore policy, which could leave level-triggered status asserted.
Actual IRQ trigger/line behavior remains a physical qualification requirement.

All earlier reset requirements remain: unique four-bank ACKs, late-fault checks,
masked/drained final observation, zero decoded FIFO counts, and quarantine on
failure. The public pause request/readback is not pause completion. Software
epoch labels and hosted IRQ models do not prove hardware freshness, outstanding
bus retirement or safe DMA release.
