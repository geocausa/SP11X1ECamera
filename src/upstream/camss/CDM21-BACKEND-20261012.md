# Dormant CDM2.1 reset backend

Patch0007 follows the six existing CAMSS source patches. Candidate10 includes
the new backend in the actual ARM64 CAMSS composite object. It introduces no
runtime parent calls, resource lookup, DT binding, IRQ registration, PM hook,
command submission, allocation or DMA release. The source remains dormant.
The earlier candidate09 is retained; source review added Linux IRQ disable
on failure because device masking alone cannot contain an un-clearable IRQ.

The parent must own a fresh powered CDM instance, its entire mapped register
extent and an exclusive Linux IRQ. Initialize zeroed storage before registering
the handler; register the handler before reset. The parent must keep mapping,
storage, IRQ and power live throughout all calls, and exclude every other reset,
submission or producer. Existing in-flight reset commands cannot be dated by a
software epoch or drained merely by synchronizing the handler.

## Implemented transaction

`camss_cdm21_init` validates the extent through the last CDM2.1 IRQ status
register, initializes locks/completion, and rejects rebinding initialized
storage. It performs no MMIO.

`camss_cdm21_reset_paused` reads the actual hardware version before writes.
Unsupported revisions receive no writes or IRQ manipulation and quarantine
the instance. Supported CDM2.1 transactions proceed as follows:

1. Mask all four IRQ banks, verify readbacks and synchronize the handler.
2. Clear all old bank status through the single bank-zero global clear command,
   then require all four status registers to be clear.
3. Request the exact public pause value3 and verify the write readback.
   CDM2.1 has no pause-complete status; this is not a pause acknowledgment.
4. Reinitialize completion and arm a unique, increasing software epoch.
   Enable only reset IRQ bit1 in all banks, with mask readbacks.
5. Under the IRQ lock, reject any status arriving during unmask before issuing
   this command. Mark the transaction issued, write reset command1, and flush
   the write before unlocking. The handler ignores pre-command observations.
6. Wait the public 300ms reset timeout. The actual ISR reads/clears all four
   banks, accumulates unique reset acknowledgments, and wakes on four ACKs
   or a fault. Duplicates do not supply another bank; status outside reset,
   inline and BL_DONE bits latches a fault.
7. Mask/drain again while the observation remains active, request pause again,
   reject late faults, close the observation, clear and verify final status.
   Only a successful transaction reads/decodes both pending counters and
   requires all four nine-bit FIFO counts to be zero.

Every supported-version error leaves the instance quarantined, requests pause,
attempts all IRQ masks, drains handler work, and disables its exclusive Linux
IRQ. There is no retry or resume API. This contains IRQ delivery even when a
mask readback fails. It does not prove hardware pause, bus retirement, or safe
power removal. Parent recovery must establish power/reset and allocation
lifetime separately; reinitializing the object to bypass quarantine is invalid.

Success is a reset observation with empty FIFO readbacks and a pause request.
It does not certify active fetch, outstanding AXI/AHB traffic, the CSID/VFE
producer, image-buffer lifetime or DMA release. The parent integration and
physical retirement proof remain required before any runtime admission.

## Provenance and validation

Register offsets, four-context layout, version, reset command, pause value and
timeout derive only from the exact Qualcomm GPL archive in
`cdm-lifetime-reference-20261012.json`, revision
`3f5ef25e12b501a518d2d4f4a870288e9bb127a0`. The earlier own portable
observation and serialization headers are copied byte-for-byte into CAMSS.
The source test requires exact candidate/header hashes and the three pinned
public files used to validate descriptors and command definitions. It compiles
the complete own backend unchanged except replacing include directives with
hosted adapters. The full public ISR/reset driver is not compiled by this test.

GCC and Clang ASAN/UBSAN each pass659 hosted cases/233600 assertions:
all24 bank orders with old completions/status, immediate and split IRQs,
missing/duplicate acknowledgments, every unexpected status bit,
stuck status/masks, status during unmask, late faults both in the handler and
latched while masked, nonzero FIFO counts, unsupported versions, extent/IRQ
validation, retry rejection, epoch exhaustion and repeated successful resets.
Twelve changed/missing/symlink candidate fixtures reject with positive controls.
Kernel locks/MMIO/IRQ/waits in this harness do not prove real concurrency or
hardware behavior.

The initial fixture wrongly expected HANDLED when injecting a second late
IRQ during failure disable after the observation had already closed. It is
retained with its failure record. The corrected fixture injects in-flight
late work only while observation is active; backend source was unchanged.
Final attempt03 also validates positive controls before pin rejection fixtures.
