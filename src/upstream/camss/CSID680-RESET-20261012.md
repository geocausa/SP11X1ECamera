# CSID680 power-up reset for independent initialization

Patch0006 follows the five CAMSS source patches. It changes the CSID680
power-up reset callback, invoked after clocks and the Linux IRQ are enabled.
The source power-on error path already propagates reset failure and unwinds
IRQ/clocks/regulators/runtime PM; that caller is unchanged. This callback must
not be reused for streaming stop or shared reset without a separate review.

The old callback combines hardware and software reset commands. The exact
Qualcomm GPL implementation chooses one command and cuts off RX before complete
software reset. The new callback follows that public command/RX policy. It first
masks TOP, reads back and drains the old handler, clears the old reset status and
rejects a status that remains set. It then reinitializes completion, enables only
the reset interrupt and issues the single software reset. A timeout masks TOP,
reads back and drains the handler before returning ETIMEDOUT. Only success
reaches the existing RDI interrupt setup. The existing 500ms policy is retained.

This is one shared initialization requirement for a provider without private
startup files. It is not a complete startup sequence, a new processed path,
physical streaming-stop acknowledgement or permission to release DMA.

The test checks 102 cases for old completion values, stale status, in-flight
old IRQ, immediate/delayed/absent/late new acknowledgement and un-clearable

for complete software reset. Initial fixture casts incorrectly treated the
halt enum as contiguous policy choices; the actual public enum also contains
RESUME. Named enum choices corrected the fixture; no initial pass is claimed.
This reinforces the rule against casting enum ordinals into hardware fields.

mutation/missing/symlink/patch rejection cases pass. MMIO, wait, completion and
IRQ primitives are hosted adapters. Their result does not prove actual hardware
IRQ latch behavior, kernel concurrency, device power sequencing or DMA retirement.
