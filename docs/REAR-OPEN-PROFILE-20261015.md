# Rear camera: open ISP start-up input and register set (2026-10-15)

Upstreaming step 1 for the rear camera (ov13858, 4064x2286 GRBG 10-bit to 3840x2160
NV12). The daily stack no longer reads the Windows-derived rear start-up input
(`rear-generation-20261007-60.bin`), and the vendor tone-mapper curve, defect and
green-imbalance settings compiled into the rear register table are switched off.
camss module 50 loads `qcom/sp11/ov13858-rear-open-v1.bin`, which `install-daily2.sh`
generates at install time from files in this repository.

## What changed in camss 50 (rear only, `unified/build-kernel50.py`)

| Part | Before | Now |
|---|---|---|
| Rear start-up input (16,672 bytes) | private file derived from the Windows rear profile | generated by `open-profile/gen-rear-open-input.py` |
| GTM tone mapper (0x5a60, 262 curve registers 0x5a64..0x5efc, 2 KB table) | vendor curve | switched off, registers and table 0 |
| PDPC (0x3d60..) and GIC (0x4760..) | vendor settings | switched off, configuration 0 |
| BPC_ABF registers | vendor values | the open values measured on the front IFE (sweep ae-44..74) |
| BPC_ABF noise LUT (`e007u`) | vendor-shaped points | our measured front noise model (`ov13858-rear-abf-v1.json`) |

`unified/camss-50/` holds the three resulting kernel source files for review.

## Sources of the open rear input

| Field | Source |
|---|---|
| Request ids, mode geometry, statistics windows/grids/thresholds/luma weights, AF window | `front-ae/tuning/ov13858-rear-startup.json`: functional values (extracted by `open-profile/extract-rear-startup.py`; the generator reproduces them bit-exactly) |
| CST12 colour transform | generated: full-range BT.601 (JFIF, chroma x 255/256), Q10; identical to what the rear used before |
| BPC/ABF parameters | the open front values (0x49b8/bc/d8/dc = 0; 0x49d0/d4/e0 saturated) |
| Lens shading (selectors 1/2) | `front-ae/tuning/ov13858-rear-lsc-v1.txt`: our flat-field measurement |
| Start 3A state | our measurement: digital gain 1.0, white balance R 1620 / B 1710 (Q10) on the neutral diffuser; PDPC channel gains follow from it |
| GTM table | zeros (module off) |

## Lens-shading measurement

SP11 lay on the SP7 with a white plastic diffuser over the rear lens; the SP7 showed
full-screen white (`open-profile/show-solid.ps1`). The rear output path subtracts a
pedestal (output rises with gain much faster than linear near black), so a one-shot fit
through an assumed tone curve is unreliable. `open-profile/rear-lsc-loop.py` instead runs
a closed loop with a lab module that admits any rear input (no digest pin): program the
mesh, capture, update every node `g *= (O_centre / O_node) ** 0.5`, repeat. After 7
iterations every channel was flat to within 6 % of its centre (corner gains about 5x).
The mesh is stored with strength 0.82 (corner gain about 3.7x, as on the front: some
natural vignetting kept to limit corner noise). Start white balance was set from
`open-profile/wb-probe.py` steps and verified: the diffuser field is neutral across the
whole frame (U 127-128, V 129-130 at centre and corners).

## Look carried over

The bridge look was fitted against Windows on the old path. `open-profile/match-look.py`
captured the SP7 chart with the old path (module 49) and the new path (module 50), same
pose, and folded the native difference into the look: tone from pixel-paired medians
(near identity: 16->15, 128->131, 224->227), chroma per axis (U slope 0.905, offset -7.7;
V slope 0.958). Old look kept in `unified/looks/history/look-rear-05.look`.

Rendered bridge output on the chart, old vs new: bright tones within 1 code, shadows
about 5 codes darker, colour patches matching; dark greys lean slightly green (old:
slightly purple).

## Remaining

- The rear has no AWB in the ISP path (fixed start white balance, as before); colour under
  other illuminants still comes from the fixed balance plus the bridge look.
- The old private rear input is still present in `/lib/firmware/qcom/sp11/` on the lab
  machine but is not referenced by module 50.
- Upstream form, as for the front: driver code / params-buffer uAPI instead of firmware files.
