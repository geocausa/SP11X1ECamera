# E010p — cold BHist request-context timing, capture aborted

Status: **the selected smaller BHist rectangle appeared after the first full-crop setter entry and before the first selector entry in one debugger-attached start; the reader timed out and no frame acceptance was obtained.** Parent E010o `f82fec86`.

On 2026-09-28, a unique rear 4K holder split enumeration, initialization and Start. FrameServer was started without a camera client and a local ARM64 CDB attached before `QcDeviceMFT8380.dll` loaded. Read-only hardware execute breakpoints were armed on `SetBHistConfigFromAlgoConfig` (RVA 0x83E8F8) and `GetBHistConfig` (RVA 0xA06BE8) at MFT load. Neither fired during the holder's initialization. After Start, the first observed setter received full crop with ROISelection 1 and a zero destination, followed by the first observed BHist selector returning the smaller ROI from a distinct request context.

A bounded read-only FrameServer private-memory scan looked for the exact four-word smaller rectangle already established by E009h. It found zero copies before Start in 14 MB scanned, zero at the first setter entry in 268 MB scanned, and 24 by the first selector entry in 280 MB scanned. The selector's actual request-context rectangle was one of the 24 matches, validating this scan against the live selected value. The scan proves an appearance within that observed interval; it does not distinguish the original writer among the 24 copies or establish a numeric request ID. The wider scan after Start covered more committed memory, so the initial zero result is not a blanket claim about inaccessible or uncommitted regions.

CDB held FrameServer while the holder's WinRT operation had a 30-second wall-clock timeout. The holder failed at StartAsync with a timeout, FrameServer exited, and no valid frame count or clean StopAsync is claimed. The debugger was closed, Windows was rebooted normally, and SP11 returned to Golden Linux with the camera overlap guard passing. This aborted run does not supersede the successful E009h/E010o physical streams.

Static Ghidra offset inventory on the same original MFT found 455 functions with a scalar matching the parent context field and 34 also containing a scalar matching the selected ROI offset; inspected IFE, BF, AWB and LSC examples showed unrelated fields or selectors. This numeric intersection is not a writer proof. The original algorithm/tuning seed and request identity remain open. Next trace the initial selected-context write with a debugger-safe holder timeout or a private time-travel trace, and verify a completed capture before promoting new causal claims. Rear hardware ISP runtime remains denied.
