# E004hm — original SPMI write callback → mapped controller command/status (offline)

**2026-09-20, offline original OEM ARM64 instruction-chain PASS; no hardware interaction.** E004hk traced the PMIC→SPMI interface and packed selector. E004hl identified the original interface slot `+0x30` as the SPMI-provider callback **`qcspmi8380.sys+0x1660`**, under the original WDF provider descriptor. This stage follows that callback to its *original low-level controller-command implementation*, instead of repeating the already-consumed PMIC flash timer/early-boot traces.

The exact original `qcspmi8380.sys` SHA256 `b6a5868ec2450e713b9a5ada7b4e1a4a77c77427fedf0806fe3eb6541099523c` shows the callback capturing packed selector **w2**, payload **x3**, and length **w4** at `+0x1688/+0x168c/+0x1690`. Its `+0x1774` descriptor-format branch selects either a direct packed-field decode or a legacy context-derived bus/address field path; the existing E004hl direct decode at `+0x177c..+0x1788` must therefore **not** be assumed to run for every request. On the direct path it separates the four-bit SID, address high and low bytes, and four-bit bus from the input selector.

Original callback `+0x17f4..+0x1818` supplies the normalized bus, SID, composed 16-bit address, original byte pointer and count to an original direct call at **`qcspmi8380+0x1870 → +0x64d8`**. This is the exact SPMI-provider **controller command helper**, distinct from the earlier PMIC driver raw helper `qcpmic8380+0x23dc8`. The provider callback preserves the return code at `+0x1874`, checks it at `+0x1878`, then returns it to the caller at `+0x18e4`. The return code is a *software controller-request result*, not a photometric observation.

Inside original `qcspmi8380+0x64d8`, the controller helper copies bus/SID/address/payload/count from the incoming registers into saved registers at `+0x6500..+0x6528`. It checks controller initialization and peripheral index and rejects missing payload or zero count on the inspected path. It derives mapped controller addresses from its pre-existing device context and sends bytes to **memory-mapped controller data registers** using original stores at `+0x674c` and `+0x6788`, followed by the original **controller command-register store at `+0x67e0`**. These stores are CPUs writing the driver’s mapped controller address space; they do **not** themselves show a packet was delivered to PMIC silicon.

The original helper initializes a finite host poll counter `0x190` at `+0x6818`, calls an indirect wait/delay routine at `+0x6844`, and reads the controller's mapped status at **`+0x684c` or `+0x6854`** until it reports a terminal condition or the iteration budget is exhausted. Original status branches at `+0x6864`, `+0x6868` and `+0x6870..+0x687c` select failures; the no-error path sets return zero at `+0x6924` and eventually returns `w21` at `+0x6b54`. The instruction verifier pins concrete error selections at `+0x6530/+0x6548/+0x668c/+0x6694/+0x6954/+0x6960/+0x6968`. **This 0x190-iteration polling loop is a host CPU timeout during a bus request—not the flash timer, an independent optical cutoff, or proof of PMIC host-crash behaviour.**

The experiment pins the unchanged original `qcpmic8380.sys` hash, PMIC encoded-selector/indirect callback callsite, the prior E004hl result, 79 exact original ARM64 instruction sites and **79 in-memory opcode mutation negatives**. Its evidence records **only addresses, function-routing facts and capability exclusions**; it does not contain original Windows binaries, firmware, original KD logs, camera imagery, face features, PMIC state or credentials.
