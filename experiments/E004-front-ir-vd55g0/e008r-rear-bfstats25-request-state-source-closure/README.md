## LUT-bank policy

The ordinary CheckDependenceChange path toggles one persistent BF LUT-bank
state. That same state is written to the request's ROI-index and gamma bank
bytes. The exact Titan680 implementation consumes that request bank for both
hardware bank registers.

This independently explains the accepted startup sequence 0/1/0/1 and matches
E006z's clean packet-phase bank provider. We therefore do **not** need a
captured bank word or a new Windows oracle.

## Feature-enable ownership

Titan680's configuration image is generated directly from semantic request
fields:

- gamma enable -> request gamma-valid field;
- luma conversion -> request input/luma configuration;
- scale enable -> request scale configuration;
- BF FIR enable -> filter substate at offset `+0xD4`;
- first BF IIR enable -> filter substate at `+0x110`;
- second BF IIR enable -> filter substate at `+0x2B0`.

Those map to the already-understood Titan config bits 9, 12, 13, 16, 17 and
21 respectively. E007b's register packer is therefore downstream-only; it
must receive these request semantics rather than inventing enable bits.

## Signed4 producer boundary

The two BCA8 signed4 nibbles are no longer opaque transport fields:

- low nibble comes from the first BF filter's semantic field at `+0x14C`;
- high nibble comes from the second BF filter's semantic field at `+0x2EC`.

The same two filter objects feed the tail helper at `+0x150` and `+0x2F0`.
This matches the DeviceMFT AF diagnostics which name the corresponding value
as the IIR filter's "number of bits to shift".

E008r closes **where** these two values come from. It deliberately does not
claim their numerical bootstrap value until the upstream AF/BAF request
producer is source-locked.

## ROI ownership

CheckDependenceChange makes the ROI boundary explicit:

- when AF supplies zero BF ROIs, helper `0xA1F4F8` constructs a single
  fallback ROI;
- when AF supplies BF ROIs, DeviceMFT copies the complete upstream AF ROI
  configuration (`0x1978` bytes) into BFStats25 state;
- helper `0xA1F578` then validates/adjusts that set against active geometry.

Therefore the accepted 25-entry rear ROI grid is **not generated by Titan680**
and is not a hidden ISP tuning table. It is upstream AF request state. The
remaining task is to reconstruct that AF semantic seed (or an independently
justified first-frame policy), not to reverse another BC08 packer.
