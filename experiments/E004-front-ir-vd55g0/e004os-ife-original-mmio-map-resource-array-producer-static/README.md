## Source-backed MMIO producer → lookup → IFE register pointer

E004or established that the original IFE initializer calls resource lookup `0x2B568` and stores its result into context `+0x140`; selectors 0,2,3 choose the first entry of global resource array `+0x50`, or first/second entry of global resource array `+0x20`, respectively (global resource table RVA`0x4AEE0`). E004os follows the actual producer of **those same pointer-array entries**, establishing that on eligible original descriptor-matching paths they receive the return of the driver's genuine imported MMIO mapper:

| Original ARM64/static source | Constrained result [S] | What remains unproven |
| --- | --- | --- |
| Original table allocator RVA `0x2B1C–0x2D00` | References global table `0x4AEE0`; conditionally allocates pointer arrays into global fields **`+0x50`** (store RVA`0x2C84`) and **`+0x20`** (RVA`0x2D00`). | Allocating storage is not proof that every runtime resource was discovered, mapped successfully or selected. |
| Original resource mapper RVA `0x2F14–0x2F34` | Loops over source resource descriptors and sets its local global-table base to RVA **`0x4A720`**. The source arithmetic **`0x4A720+0x810 = 0x4AEE0+0x50`** and **`0x4A720+0x7E0 = 0x4AEE0+0x20`** connects its two storage fields to the IFE lookup's arrays. | The live device's resource-descriptor inventory and physical IFE index. |
| Conditional first/second resource-`+0x50` branches RVA`0x31AC–0x3214` | Distinct name/descriptor matches use descriptor physical-start field `+0x18` as first argument and descriptor length field `+0x20` as second argument, set third argument `0x4`, and call the pointer loaded from original ntoskrnl IAT RVA **`0x3F170`**. The IAT is independently identified as **`MmMapIoSpaceEx`**. | Lookup `0x2B568` → IFE init `0x22408–0x2248C` | The source-verified lookup returns the selected mapped-array pointer into context `+0x140` and, on its nonnull path, builds selected register window `+0x150` using the `0xC00`/ `0x1200` mode-dependent offsets. | An active mode, live base address, fully retired WM16 DMA, or Linux optical rear hardware-ISP output. |

**This closes the original static MMIO-mapping *provenance* rather than pretending a software array contains an arbitrary pointer.** The code identifies a real conditional `MmMapIoSpaceEx` producer and its actual downstream IFE consumers. It does **not** prove that the Windows rear session selected either of those resource-array entries, what physical IFE instance was mapped, that an MMIO write is a completion acknowledgment, or that native Linux should copy Windows device-resource allocation.
