# E004js — one-use camera-enabled, **non-streaming** media graph diagnostic

2026-09-20. Source-locked successor to **consumed/retired E004jq** (which failed before optical capture due to missing media discovery evidence). Parent `b1dd273`. This is a NEW one-shot whose sole objective is to preserve actual bounded non-image `/dev/media*` and `media-ctl` topology/command-error evidence **after** the exact accepted camera modules bind, while leaving all cameras unstreamed.

The only hardware actions in the isolated camera-capable candidate are to bind the same accepted CAMSS, rear OV13858, front IMX681 and infrared VD55G0 modules that had successfully probed in E004jq. Sensor registers needed for normal driver probe may be written; no V4L2 stream, media-link configuration, test-pattern capture, sensor output file, /dev/video90, virtual camera or IR illumination is requested. Keep front and IR in standby. An isolated GPL module is **not needed** for this diagnosis.

The runner verifies committed Git/head/origin and 51-file SHA-pinned original camera package, selected module hashes, original protected Golden saved boot and empty next_entry, successful and ordered GRUB writers, unique candidate command line and single-use marker. It then inspects root-private sensor bind status, ordinary video/subdevice/media node names and invokes the bounded E004jr diagnostic to preserve up to eight `media-ctl -p` topologies and their failures under an eight-second aggregate budget. Successful **diagnostics** are useful even if the expected unified graph is incomplete. All raw topology/kernel logs remain root-private and are deleted after redacted status summarization. The service requests Golden reboot on exit, error or timeout; it does not modify the persistent boot default, original kernel/DTB/initrd, or other candidate identities.

`E004js` must be armed **exactly once** after source tests and unarmed root-copy stage pass. Do not reuse E004jq or imply that a successful graph inventory establishes a live 4K webcam or working front QC10C conversion. Only a new, separately source-locked optical streaming candidate can do so after this diagnostic identifies an actionable graph state.
