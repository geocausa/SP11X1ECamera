# E004hc — original Windows flash-to-PMIC interface and exact IOCTL route (OFFLINE PASS)

**A new, concrete cross-driver request path, verified against the original hash-pinned Windows ARM64 binaries.** This stage identifies which OEM interface the flash driver obtains and the PMIC dispatch branch that accepts one of its command IOCTLs. It does **not** execute a fresh Windows preview/KD session, touch any PMIC registers, activate a light source or change Golden Linux.

Original `qcpmic8380.sys` SHA256 `756b5c2e4eb8d5a2bdc0dcc0f7f5703eef79dec0c963155c54e42097bc2f790e` contains interface GUID `20952871-af3d-4a8a-9e47-cb346507b95b` at RVA `0x36fb8`. Its code at RVAs `0x2574–0x259c` passes the GUID as argument `x2` into an indirect WDF function-table call (the exact WDF method name has **not** yet been independently resolved). Original `qccamflash8380.sys` SHA256 `6bc1d698bc3b6da16974cd6f3ea89dc1ba6a8ea102eebe1a5d41129b4eb9ba2b` contains the **byte-identical GUID** at RVA `0xd858`; at RVA `0x49fc–0x4a20` it passes that GUID to the original `IoGetDeviceInterfaces` import, followed by `IoGetDeviceObjectPointer`. The latter writes the target device object to flash global RVA `0x2a7d0`.

The original flash command wrapper RVA `0x4d58` builds a **four-byte input packet** and loads literal `IOCTL 0x802f0fc8` from flash RVA `0x4dc8` before calling its sender at RVA `0x4ac0`. That sender reads the **same global device object** at `0x2a7d0` and invokes the original imports `IoBuildDeviceIoControlRequest` then `IofCallDriver`. Original PMIC `qcpmic8380.sys` contains the **identical `0x802f0fc8` value** at RVA `0x7c10`; its dispatch code at `0x71e0–0x71e8` compares the incoming request code to that literal and branches to **RVA `0x7378`** on a match. That branch checks the request input length is exactly **four bytes**, calls a PMIC readiness/helper routine at `0x7394`, then forwards the request through an indirect callback loaded at offset **`0x90`** from its current handler object. The underlying handler object/target for a normal OEM preview must be resolved separately; a matching IOCTL and code path do not show a completed bus write, emitted light or an autonomous timer.

**Important path distinction:** the newly connected **flash IOCTL receiver at PMIC RVA `0x7378` is not proven to be the generic raw register-write callback RVA `0x32b70`** found in E004gz/E004ha. E004hb's unexercised generic callback was not a positive control; the flash command and exact PMIC dispatch give us a different and better-defined lifecycle boundary. To chase the original Windows timer-register initializer, first determine which target occupies the receiver's **offset-`0x90`** slot for the OEM flash device and whether it ever requests `ee3e–ee41` through any internal PMIC helper or transport. Do not repeat previously consumed identical early-boot no-hit watchers or assert a first writer without a recorded request.
