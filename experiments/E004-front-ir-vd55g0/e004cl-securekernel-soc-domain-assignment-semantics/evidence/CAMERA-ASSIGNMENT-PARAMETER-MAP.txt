API / SECUREKERNEL ARGUMENT MAP
IumSdk user-visible call shape:
  AssignMemoryToSocDomain(section, page_array, page_offset, page_count, io_domain, protection, flags)
IumBase prepends output assignment-handle pointer before entering IUM SVC #0x8000.
SecureKernel signature therefore maps as:
  param_1 = output assignment handle
  param_2 = secure-section handle
  param_3 = optional caller page/IPA array
  param_4 = page offset
  param_5 = page count
  param_6 = IO domain
  param_7 = protection
  param_8 = flags

CAMERA VALUES
  io_domain = 0x0d
  protection = 4 (Windows PAGE_READWRITE class)
  flags = 0

SECUREKERNEL TRANSLATION
  protection 2    -> device GPA flags 0x1
  protection 4    -> device GPA flags 0x3
  protection 0x20 -> device GPA flags 0x0d
  protection 0x40 -> device GPA flags 0x0f
Therefore camera protection=4 becomes device GPA R|W flags 0x3.

DOMAIN AUTHORIZATION
SkhalValidateProcessIoDomain(process_policy, io_domain) walks the secure process policy's IO-domain list and succeeds only on an exact domain match.
Thus 0x0d is a policy-authorized secure-process IO domain, not inferred here as a replacement physical-page owner.
