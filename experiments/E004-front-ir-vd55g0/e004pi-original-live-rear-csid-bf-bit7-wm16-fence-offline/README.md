## Safe native integration boundary

Same-SP11 accepted native Linux `camss-csid-680.c` already latches CSID BUF_DONE status+0x8C, writes BUF_DONE clear+0x94 and issues the CSID IRQ clear command. It accounts for other named front/statistics bits, not a validated **rear WM16 DMA release** on CSID bit7. The accepted `camss-vfe-680.c` **real VFE680 ISR is still only `return IRQ_HANDLED;`** (E004ow), and there is no validated native VFE1 WM16 per-generation BUS/IRQ/DMA/IOMMU quiescence producer. The E004nv six-group rear candidate is compiled but unwired and runtime DENIED; the E004ov owner/stop model remains offline. **Do NOT double-ack CSID in VFE ISR, relabel CSID BUF_DONE bit7 as VFE WM16 completion, treat a static FIFO8 event as a DMA fence, enable the candidate, release a buffer or hand VFE1 back to front on this status alone.**

E004pi adds a separate **standalone, entirely offline C11 domain gate** `bf-wm16-domain-gate.h` and regression tests: the observed CSID bit7+mask, WM16 CFG0 enabled, nonzero WM16 ADDR_STATUS0 and zero sampled BUS STATUS0/1 can never retire a frame without **independently sourced and generation-matched** VFE1 WM16 IRQ/ack, bus quiescence, DMA completion, IOMMU ownership and source/owner/stop/FIFO8/group fences. It rejects substituted CSID-as-VFE evidence and owner/frame/FIFO mismatches. A synthetic *hypothetical* all-evidence example may pass the offline predicate, **but no accepted native hardware producer exists to provide that evidence, and the separate actual runtime authorization function ALWAYS returns `-EOPNOTSUPP`**. Nothing is called or included in the accepted kernel; no hardware runtime, IRQ registration, DMA operation or boot configuration changed.
