# E004gx — distinct early Windows hardware breakpoint on OEM PMIC helper

Goal: revisit the zero-hit **software** breakpoint results from E004gv/E004gw using the successful hardware breakpoint method documented in SP11 AUDIO `00-ground-truth/04-gpio-pinctrl.md`. During audio boot tracing, software INT3 breakpoints missed two early GPIO writes, whereas `ba e1 qcaucd8380+0x52060` caught both. E004gx tests the hypothesis that early KDNET code patching/missed traps obscure OEM PMIC activity. It is not a native Linux LED experiment or a rerun of prior consumed camera trace IDs.

Preflight: ensure SP11 protected Golden v19c, tracked-clean synchronized camera experiment branch, no camera nodes/processes/modules, EFI BootNext empty; ensure SP7 has no active KD process, existing local KDNET key available and a new log path. Start SP7 KD `-d -bonc` **before** one-time Windows Direct boot. At first target pause check `.time; lm m qcpmic8380`; if PMIC unloaded, enable `sxe ld:qcpmic8380`, continue, inspect kernel uptime/live module and helper RVA `0x23968` on load event. At actual live PMIC module address arm a single **hardware execution** breakpoint `ba e1` on the original generic PMIC masked-write helper. Its command records up to eight **non-emitter** initial calls as a positive control and filters w2=0xee3e..0xee41 for original timer-register requests; after a real timer hit capture registers and shallow caller stack, auto-continue. Do not use an ordinary software `bp`/`bu` as a substitute or infer no writes merely from an armed but untested breakpoint.

Only natural Windows boot/idle, NO Camera/OEM preview, flash request, driver restart, PMIC write, firmware modification, held strobe, fault injection, image capture or native Linux emitter. Hardware breakpoints are CPU/thread-context dependent; a control hit demonstrates the actual execution watch worked for that call/core, **not coverage of all cores or the early pre-attachment interval**. KD symbol/load timing must be verified before claiming coverage. If no safe positive control arrives in a bounded observation, classify the result inconclusive and trace a known safe callback in a separate new experiment. Explicitly clear all KD breakpoints/exception filters, close original log and resume Windows. Normal Windows restart to protected Golden and verify EFI, GRUB and camera-idle guard. Archive original non-secret SP7 trace byte-for-byte and mark one new boot identity consumed. This plan is not a proof of near-IR optical output or electrical autonomous cutoff; E004fs/E004ge stay BLOCKED.
