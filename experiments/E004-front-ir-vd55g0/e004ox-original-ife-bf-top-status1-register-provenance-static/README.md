## Crucial IRQ clear discrepancy — do NOT write guessed registers

The original snapshot's subsequent **TOP-side** writes at RVA0x1DCB4/0x1DCC8/0x1DCE0 use original-base +0x3C,+0x40,+0x30, numerically matching accepted non-lite Linux TOP clear0/clear1 and IRQ_CMD offsets. However, its **BUS-side** writes at RVA0x1DCF0/0x1DCFC/0x1DD04 use selected-window **+0x3C/+0x40/+0x30**, i.e. mode-zero original base **+0xC3C,+0xC40,+0xC30**. The accepted Linux non-lite **BUS IRQ clear0/clear1 are base+0xC20/+0xC24**, and BUS global clear is +0xC30. `0xC3C/0xC40` **do not equal** `0xC20/0xC24`. Do not transplant original writes, call the whole callback a proven Linux IRQ-clear recipe, or infer a safe WM16 IRQ/DMA fence from either pair. This mismatch can reflect additional OEM-specific status/mask semantics, an alternate register window or an unresolved mapping; it is **not resolved** by the current bounded evidence.
