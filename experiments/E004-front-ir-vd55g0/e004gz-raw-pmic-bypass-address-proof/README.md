# E004gz — classify three original OEM PMIC raw-write bypass callers (OFFLINE)

**Completed 2026-09-20; the original 0x93 timer-register initialization owner remains unknown.** Original OEM `qcpmic8380.sys` ARM64 PE SHA256 `756b5c2e4eb8d5a2bdc0dcc0f7f5703eef79dec0c963155c54e42097bc2f790e` has exactly four direct `bl` calls to the original raw-write helper RVA `0x23dc8`: the masked-write callsite `0x23a04` from E004gx/E004gy and three distinct bypass sites `0x2fc54`, `0x303b4`, `0x32c2c`. No new Windows/KD/PMIC/camera/emitter experiment occurred in E004gz.

The **`0x2fc54` bypass** forms the raw-write start address as `0xfd00 | u8` and supplies a byte count read as `u8`, so its start lies at least `0xfd00`, strictly beyond timer addresses `0xee3e–0xee41`. No forward write length can make that starting address overlap the lower timer range. The **`0x303b4` bypass** forms its start as `input | 0x49` and requests exactly two bytes. Any two-byte span intersecting `0xee3e–0xee41` must begin at one of `0xee3d, 0xee3e, 0xee3f, 0xee40, 0xee41`; none has all the address bits forced by OR `0x49`. Thus **these two direct bypass callsites cannot themselves request raw writes overlapping those four timer addresses**, under the verified original ARM64 argument construction. This is an address-range statement, not proof that other helpers, firmware or any hardware cannot alter those registers.

The **`0x32c2c` bypass remains address-capable**: the original raw-write call passes a caller-supplied 16-bit register address (from `w1`) and caller-supplied 8-bit byte count (from `w2`) after saving its buffer pointer. The wrapper entry is RVA `0x32b70`. It has **no direct ARM64 `bl` callers in the executable sections we scanned**, but the genuine 64-bit Windows driver callback pointer at `.data` RVA `0x3a510` points at it. Its additional references in the Guard CF allowed-target and `.pdata` unwind tables are metadata, not runtime callers. The dispatch-table owner, caller/operation ID, actual exercised register addresses and relationship to Windows early boot or camera configuration are not yet recovered. E004gy's bounded hardware-breakpoint window recorded only the masked-write caller, so none of these three other paths was observed in that interval.
