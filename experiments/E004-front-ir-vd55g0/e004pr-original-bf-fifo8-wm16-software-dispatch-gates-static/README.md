## Where the observed BF assignment sits relative to actual queue and hardware

The original mode-zero handler uses CSID-derived normalized status bit7 at RVA **0x1F048** and builds a *local array* of candidate event IDs. The **actual E004pq Windows hit at 0x1F190** is merely `mov w15,#0x0F`; original 0x1F194 writes it into this local event-ID array. It does **not** prove iteration selected event0x0F for the same queued type1 record or successful group8/FIFO8 dequeue. The independent original dispatch site **0x1FC60** compares the iterated ID to `0x0F` before taking the BF-specific branch. Even in that branch, **0x1FC94** requests **FIFO group index 8** through the dequeuer0x26460 and **0x1FC9C** explicitly branches away when its `x23` return is null. The original queue helper itself checks the queue and pending count at RVA0x26514–0x26524. Thus neither *BF status bit7* nor *observed 0x1F190* can prove that a live BF FIFO8 output buffer existed.

**For a nonempty group8 entry only**, branch 0x1FCA0–0x1FCC4 invokes mode-zero per-event status callback from the device function slot +0x6B6C0 with `event_id=0x0F` and scratch=device+0x178. The BF-specific original callback RVA0x1D710–0x1D728 reads the device register window **+0x1270** to scratch+0x4C and **(+0x1200 & bit0)** to scratch+0x48, later read as device+0x1C0 at RVA0x1FCC8. If the lowbit is zero, branch0x1FCCC skips extended BF metadata; **the source has not proven that reading this enable/configuration bit is an independent DMA completion fence**. When nonzero, RVA0x1FCDC/0x1FCE0 reads **FIFO8 entry identity+0x08 and tag+0x16** and RVA0x1FCE4 calls outstanding-entry matcher0x25078, which compares identity and 16-bit tag across up to six entries (RVA0x250B4–0x250D4). It stamps BF resource port **0x300D** (0x1FCE8), copies the popped entry's identity/tag to device+0x590/+0x5A0, stores the retained entry at **device+0x6A8** (0x1FD18), builds software event record0x1A in device+0x520 and invokes generic **software** callback0x26340 at RVA0x1FD28 (return checked0x1FD2C). That callback routes through an original device function slot +0x130; even an observed *successful* software callback alone would **not be a same-buffer VFE1 WM16 BUS/IRQ DMA/IOMMU retirement fence**. This clarifies the earlier E004nv static callchain and E004pq actual instruction hit without asserting live group8 or hardware-safety evidence never captured.
