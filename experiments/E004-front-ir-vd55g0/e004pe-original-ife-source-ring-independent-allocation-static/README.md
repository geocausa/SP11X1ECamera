## Original source evidence and corrected owner

In the original same-SP11 ISP, the coordinator works with distinct per-instance endpoint-table entries. At original RVA`0x175F8–0x17610`, it loads **table+0x40**, computes the selected per-instance slot, saves the slot in the local stack and forms its endpoint pointer at slot+0x08. RVA`0x17660–0x176C0` creates a new endpoint object with generic core callback0x211B0/teardown callback0x21C00, allocates the endpoint's context and loads it into x19 from endpoint+0x20. RVA`0x17A90–0x17AF0` then allocates/initializes a **0x1D0-byte ring object** and stores the pointer at **this endpoint's context+0x1B0**. Original RVA`0x17BEC–0x17BF4` loads the saved selected slot+0x08 and stores that **same endpoint object** in the per-instance table. This associates the 0x1D0-byte context+0x1B0 ring specifically with **table+0x40, the command-B DESTINATION endpoint**. The original context+0x1B0 ring is also accessed in original setup0x17B34 and context cleanup0x21F28, but those accesses are not evidence about the different source endpoint.

By contrast, original channel setup RVA`0x17FB8–0x17FE4` selects **table+0x30, the command-A SOURCE endpoint**, invokes its generic core command0x0A, then RVA`0x17FFC–0x18024` selects **table+0x40, the DESTINATION endpoint**, and passes the same 24-byte kind-2 interface via command0x0B. Original core callback command0x0A at RVA0x214BC returns **the SOURCE context+0x1B0 pointer** into interface+0x00; command0x0B at RVA0x21478 imports interface+0x00 into **destination context+0x198**. This is the real E004pd source→destination pointer transfer. Crucially, **the allocation site for the SOURCE endpoint's context+0x1B0 was not established in E004pe**; the destination's unrelated same-offset ring cannot be substituted.

The original independent IFE event worker allocates a **0x368-byte ring at worker device+0x08** (RVA0x22830–0x22898) and dequeues via RVA0x23900–0x23940. The 0x1D0-byte **destination** ring and 0x368-byte worker ring have independently verified original allocator sites, but the identity of the command-A **source** ring relative to either object remains open. Do not assert that the 0x1D0-byte destination ring is the source ring, that destination/source/worker rings alias, or that they never alias during any live session. The source-side ring consumer, exact type-1 record-to-worker path, and selected rear4K snapshot-buffer provenance still require investigation.
