# E004jv — bounded 4K GStreamer app real-arrival telemetry, offline source gate

2026-09-21. Parent `cad8f1d`. **Source-only on protected Golden**; no hardware camera, V4L2, boot/GRUB, front sensor or IR interaction. Intended as an independent standard V4L2 subscriber's *application sink* in a future UNIQUE candidate, following E004ju's real physical rear 4K→standard webcam→8-frame app test. It does **not** directly open any camera.

The original E004jn app intentionally assigned **synthetic 30fps PTS** and consumed at most 8 4K NV12 frames, so its 228 ms interval cannot independently establish app-visible sustained cadence. New E004jv accepts up to **120** complete NV12 3840×2160 frames on stdin, pushes them into real bounded GStreamer `appsrc→queue→videoconvert→I420 appsink`, validates every 12,441,600-byte sample and synthetic PTS, and measures `time.monotonic_ns()` in the **actual appsink callback**. It emits first-to-last wall-clock observed app frame rate, p95 and maximum interarrival spacing and total pipeline interval. It also hashes only three sampled decoded buffers in memory, reporting whether their pixels vary **without emitting image bytes or hashes**. A static scene or unchanged exposure can legitimately produce identical frames; the variation flag is diagnostic, not a stream health verdict. No physical source claim is embedded in the app, and every pass line explicitly says synthetic PTS and live camera not independently proven.

**Four camera-free tests PASS**: three distinct synthetic 4K NV12 frames preserved through I420 with measured wall-clock callback timing (unpaced local frames can show >30fps), truncation and extra-byte rejection, frame bound 1–120 rejection and source nonactivation. No image or test frame files are written.

Independently compare actual source hardware timestamps, virtual buffer sequences and **appsink real arrival times**, report dropout/thermal/latency limitations and never infer 4K30 from fabricated PTS or from a static synthetic test.
