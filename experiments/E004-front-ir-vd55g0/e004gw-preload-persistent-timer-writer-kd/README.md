# E004gw — original PMIC generic timer request during early Windows boot

NEW independent Windows/KDNET identity. E004gv established that SP7 KD -d -bonc pauses Windows before qcpmic8380.sys appears, but its one-shot timer observer was armed only after the second break and vanished without a matching hit marker. This E004gw stage addresses BOTH gaps.

Hypothesis: the original Windows boot-start PMIC driver may configure timer registers 0xee3e..0xee41 through original qcpmic8380.sys generic masked-write helper RVA 0x23968 during startup. At that entry, w2 is the register address, w3 mask, w4 requested byte. A PERSISTENT symbolic deferred address-filtered breakpoint armed at the FIRST KD pause can identify an actual software caller or bound its absence during the observed interval.

Preboot scope: verify Golden, synced clean tracked Git, independent SP7 KD access, unchanged EFI BootOrder/Golden v19c and no camera process. Open new SP7 KDNET listener -d -bonc with a unique original log and locally stored key (never print key). Arm one-time Windows Direct EFI BootNext. At first KD break inspect .time and loaded PMIC modules; if qcpmic8380.sys already loaded, ABORT any first-writer conclusion and return Golden. If not loaded, validate no existing KD breakpoint and arm a symbolic DEFERRED PERSISTENT conditional bu /w with condition w2>=0xee3e && w2<=0xee41 at qcpmic8380+0x23968, never with /1. If matching: log entry w0..w4 and shallow stack, disarm this breakpoint and automatically continue. Resume; at subsequent debugger break verify the PMIC image and that the deferred breakpoint resolved and remains active before driver startup continues. If not, abort any no-hit conclusion.

Observe only natural Windows boot/idle, without Camera, face auth, flash, PMIC writes, fault injection, held strobe or sensor reset. Window at most 90 seconds of kernel uptime. Manually pause KD at Windows idle, inspect matching hit markers AND breakpoint list, clear all breakpoints, disable load events, close original KD log and continue. Normal Windows reboot to untouched persistent Golden Linux, verify camera-idle guard and EFI/GRUB state; preserve original SP7 log bytes and digest in this NEW stage. Previous E004gb/E004gs/E004gt/E004gv identities remain consumed.

Interpretation: a matching callback entry hit shows original Windows software register request and caller stack, not successful physical write or safe LED output. No hit plus persistent resolved breakpoint remaining armed at teardown bounds only this generic PMIC helper in that interval; it does not exclude other hardware/firmware/generic write mechanisms or the first KD-unobservable boot seconds. Missing/disappeared unresolved hook means INCONCLUSIVE, not no-write. Native Linux emitter/PAM OFF, E004fs/E004ge electrical/optical safety BLOCKED.
