## Original mode-zero dispatch has two distinct event-record paths

[E004nv's original-source BF addendum](../e004nv-rear-six-group-bf-static/STATIC-BF-CALLCHAIN.md) identified the **type-1** original mode-zero IFE event path, including incoming second status word bit 7 → event `0x0F` → independent FIFO8 dequeue → BF callback reading actual WM16. E004ou source-locks the **other type-2 event-record branch** of that same handler and compares its register/queue semantics with the already identified BF path:

| Original original-ISP RVA / conditional branch [S] | Exact bounded behavior | Safety/evidence limit |
| --- | --- | --- |
| `0x1EFD8–0x1EFE8`, `0x1F048`, `0x1F188–0x1F194` | Only event-record **type 1** takes the status-word event-list builder: extracts bit7 of second incoming status word and, if set, appends event ID `0x0F`. The independent BF event branch at `0x1FC60` dequeues group **8** at `0x1FC94`. | This is static conditional availability; no live rear 4K BF event or actual FIFO8 item is proven. |
| `0x1D710–0x1D728` | The separate **BF-specific** per-event callback reads `selected_window+0x1270` and `selected_window+0x1200` (CFG0 bit0). In original *mode zero*, E004or's source-checked selected window is `original_base+0xC00`, yielding WM16 **ADDR_STATUS0 `base+0x1E70`** and **CFG0 `base+0x1E00`**, respectively. | Reading WM16 address status and enable bit to populate completion metadata is NOT independently a bus-stop/IRQ-ack/retire fence. |
| `0x1FECC–0x1FEE8` | **Type 2**, not type 1, loads an event-record pointer from record+0x08 and tests that record's `+0x0C` flags against `0xC0000000`. If flags do **not** match, it skips the subsequent diagnostic register reads entirely. | No branch here tests BF event ID `0x0F` or pops FIFO8; the conditional flag is not a measured WM16 completion bit. |
| `0x1FEEC–0x1FF0C` | When those type-2 flags match, reads `selected_window+0x64` and `selected_window+0x70` **for a diagnostics call**. They are not used as a predicate to authorize the type-2 counter decrement. |
| `0x1FF10–0x1FF48` | Uses `LDAXR/STLXR` and `DMB ISH` to atomically decrement **a software counter in the event-record object**. If it reaches zero, clears the record and invokes **a separate queue helper RVA0x2BEF8** on software context+0x33C8. The queue helper has its own storage/space checks; it is **not** the BF FIFO8 pop helper RVA0x26460. | Neither the counter reaching zero, record clearing nor queuing proves a physically retired BF WM16 DMA transfer or live VFE IRQ acknowledgment. |

This closes the previously ambiguous **type-2 software-count versus type-1 BF group8 separation**. No original instruction in the bounded type-2 branch reads the BF WM16 registers or checks their retirement status, and its optional diagnostic MMIO reads cannot substitute for a DMA fence. **Do not extrapolate** that there is no hardware-driven event/IRQ source or no other hardware completion/ack path outside the bounded branch.
