**2026-09-24; parent E004pk Git `d464f5e62f2de9a891c927f5a0cf1a5caf3277a2`.** This corrects the earlier claims that the E004PS debugger captured *no useful hits*. The original Windows OEM ISP was loaded on SP11 and its true relocated PE image was identified; the SP7 debugger first attempted unresolved module-relative expressions, then **removed those** and re-armed four **verified absolute** source RVA locations after checking live decoded original ARM64 instructions. Those absolute /1 breakpoints auto-continued with `gc`. A complete **354-line private E004PS debugger log** is retained **only on SP7**, with original SHA256 `b9bd34f68101d987b7d86cb0de3ca713f26a62fab39295ec4661157fe250ffcc`. It was read and hashed on SP7 through Fabric; neither the OEM binary nor the private log, live kernel addresses, context pointers, original stacks, pixel data or DMA/physical addresses is committed or copied. This SP11 Linux `verify.py` revalidates four same-SP11 original OEM instruction identities and the recorded safe-scalar ledger, **but does not pretend to independently rehash the unmounted private SP7 log**.

The **three real marker lines** were 341, 346 and 351, in config-test→zero-preparer→BF-event-instruction order, **after** the four absolute breakpoint instructions were disassembled, re-armed and resumed. The prior *symbolic* `qccamisp8380+offset` breakpoints were unresolved and cannot be counted as hits. The SP11 original Windows rear-4K task E004PN completed two passes (653 and 1,154 valid handles, total 1,807) in this series of Windows debugging experiments; **neither its safe task result nor the SP7 KD log provides an exact shared timestamp, instance/owner ID, frame-generation marker or FIFO8/WM16 queued-buffer ID for each KD hit**. Therefore this result is **P (a real original Windows driver instruction was executed)** but **NOT P for one matched rear-4K frame, BF event dispatch or WM16 DMA retirement**. Historical E004nv/nq/pi/pk verifiers retain their original false live-BF conclusions *within their earlier observation windows*; E004pq adds a new, narrowly scoped live instruction observation rather than silently rewriting older source evidence.
