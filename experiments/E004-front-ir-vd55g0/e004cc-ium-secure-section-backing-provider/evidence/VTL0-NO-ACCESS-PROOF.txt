Official Microsoft Hyper-V TLFS cross-check:
https://learn.microsoft.com/en-us/virtualization/hyper-v-on-windows/tlfs/hypercalls/hvcallmodifyvtlprotectionmask
- HvCallModifyVtlProtectionMask call code = 0x000C (Rep)
- input offset +0x00 TargetPartitionId
- input offset +0x08 MapFlags
- input offset +0x0c TargetVtl
- MapFlags is the VTL GPA protection mask.

https://learn.microsoft.com/en-us/virtualization/hyper-v-on-windows/tlfs/vsm
- higher VTLs enforce Read/Write/Execute access protections for lower VTLs
- permission mask 0 means no Read/Write/Execute access
- VTL0 is the lower/normal trust level; VTL1 is more privileged.

ShvlpProtectPages builds exactly that input shape:
- +0x00 = 0xffffffffffffffff (self/current partition sentinel)
- +0x08 = requested protection mask
- +0x0c = 0 (target VTL0)
- Hypercall code = 0x000c

-> SkmiProtectPlaceholderPages(... access_index=0 ...)
